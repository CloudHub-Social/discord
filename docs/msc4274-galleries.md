# MSC4274 attachment galleries

The bridge sends Discord messages with at least two successfully transferred attachments as one experimental `dm.filament.gallery` Matrix message. Its item format matches Ruma revision `0ed7fba34213f18a628a56f527c6cc795cd7eef5`, used by Sable v2 at the time of implementation. Other clients may display only the fallback text; set `bridge.discord_attachment_galleries: false` to keep separate attachment events for clients without gallery support. Messages with stickers, separate video embeds, or an attachment transfer failure retain the existing separate-event behavior. Single attachments retain the normal bridge path.

A Matrix gallery is sent as one Discord message, with at most 10 supported file, image, video, or audio items. Filenames, available descriptions, order, MIME type, and the `page.codeberg.everypizza.msc4193.spoiler` flag are preserved where Discord supports them. Discord does not retain Matrix dimensions or duration supplied as metadata; its own media processing determines those. Matrix captions and per-item descriptions use the existing text conversion and Discord's attachment-description field.

The bridge limits a gallery's combined downloaded media to 100 MiB for user-session CDN uploads and 24 MiB for multipart uploads, leaving room under Discord's 25 MiB multipart request limit. Discord may impose a lower account or channel limit. Invalid, unsupported, oversized, or undecryptable items fail the gallery as a whole rather than silently omitting files.

Gallery edits replace the existing Discord message's attachments; text-only edits preserve existing attachments and update the caption; Discord-side edits refresh the full message before creating a Matrix replacement. Converting an existing non-gallery Matrix message into a gallery by editing it is not supported. A gallery reduced to one item can lose its separate item description when the single-item Matrix caption is also needed. Other Matrix clients may not support gallery edits or spoilers.

The bridge reserves outbound Matrix gallery sends before the Discord request. If a response is lost, a matching user-session gateway echo can reconcile the message; otherwise the reservation blocks another send until an operator verifies the Discord channel and resolves the reservation. Webhook sends have no nonce-based reconciliation and require this manual check after an uncertain response. See the migration note before rollout or rollback.
